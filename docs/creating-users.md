# Как устроены аккаунты FlyGuru

Публичной регистрации нет. Способ выдачи доступа зависит от роли: сотрудники
используют Supabase Auth, агент сначала создаётся как бизнес-сущность в админке,
а участник клуба входит через Telegram Mini App.

## Сотрудники

Для `admin`, `dev`, `instructor`, `mechanic`, `smm` используйте только
`scripts/create-user.mjs`. Он выполняет два необходимых шага: создаёт Supabase
Auth-пользователя с ролью в JWT и строку в таблице `users`.

```bash
# Администратор — вход по email
node scripts/create-user.mjs --role admin --name "Денис" \
  --email denis@example.com --password "длинный-уникальный-пароль"

# Инструктор — вход по телефону; технический email создастся автоматически
node scripts/create-user.mjs --role instructor --name "Иван" \
  --phone "+84 90 123 4567" --password "длинный-уникальный-пароль"

# Сотрудник с настоящим email и телефоном
node scripts/create-user.mjs --role mechanic --name "Сергей" \
  --email sergey@example.com --phone "+84 91 234 5678" \
  --password "длинный-уникальный-пароль"
```

Если создание Auth прошло, а запись `users` не создалась, скрипт выводит
инструкцию удалить незавершённый Auth-аккаунт перед повтором. Не создавайте
вторую строку с тем же человеком наугад.

## Агент

Агента сначала создают через административный интерфейс. В этот момент
появляются его строка `users`, запись `agents` и реферальный код. Если агенту
нужен личный кабинет `/agent`, добавьте вход к уже существующей записи:

```bash
node scripts/grant-agent-login.mjs --code AB12CD \
  --email agent@example.com --password "длинный-уникальный-пароль"
```

Не вызывайте для такого агента `create-user.mjs`: он создаст другого
пользователя, не связанного с существующим реф-кодом и статистикой.

## Участник клуба

Участнику не нужен Supabase Auth-аккаунт и пароль. Рабочий поток:

1. Администратор заводит клиента и абонемент.
2. Клиент открывает клиентского Telegram-бота и делится своим контактом.
3. Webhook проверяет секрет Telegram и сопоставляет нормализованный телефон с
   клиентом.
4. Telegram-профиль связывается с клиентом, и Mini App открывает `/member`.

В репозитории остались legacy invite/password-функции для участника. Они не
являются рекомендуемым способом онбординга и не должны использоваться для
новых клиентов, пока поток не согласован и не исправлен целиком.

## Смена роли

Роль дублируется в `users.role` и `app_metadata.role` Auth. Ручное изменение
только одной стороны приводит к рассинхронизации доступа, поэтому используйте:

```bash
node scripts/set-role.mjs --role admin --email boss@example.com
node scripts/set-role.mjs --role instructor --phone "+84 90 123 4567"
```

Сейчас скрипт поддерживает `admin`, `instructor`, `mechanic`, `smm`, `member`,
`agent`; `dev` в его списке пока отсутствует. После изменения роли пользователь
должен выйти и войти снова.

## Смена пароля

```bash
node scripts/set-password.mjs --email user@example.com \
  --password "новый-длинный-уникальный-пароль"
```

Можно искать и по `--phone`. Для обычного восстановления сотрудник также может
использовать штатный reset password, если почта настроена.

## Почему не вручную через Supabase Dashboard

Ручной способ легко оставляет роль только в одном месте, неверный `auth_id` или
дублирующую строку. Dashboard полезен для диагностики и удаления незавершённого
Auth-пользователя, но штатное создание и изменение аккаунтов должны идти через
скрипты выше.

## Проверка доступа

- Вход сотрудника выполняется через `/login`.
- Инструктор попадает в `/instructor`, механик — в `/mechanic`, SMM — в `/smm`,
  агент — в `/agent`, администратор — в `/admin`.
- Пользователь не должен открывать кабинет чужой роли.
- Участник открывает `/member` из корректно подписанного Telegram Mini App, а
  не через общий password login.

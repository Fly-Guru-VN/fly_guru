# Исправления четырёх приоритетных находок, 05.09.2026

Изменения подготовлены локально. Production, webhook и внешние настройки
не изменялись. Остальные находки аудита в эту пачку не входят.

## Что изменено

1. `0055`: прямые записи инструктора в sessions, механика в bookings и полевых
   сотрудников в expenses закрыты. Формы пишут через сервер после проверки
   активной роли; удаление личного расхода дополнительно ограничено created_by.
   В БД запрещены отрицательные суммы/комиссии и неположительные минуты/расходы.
2. `0056`: Mini App ищет полный нормализованный телефон через индекс, а не хвост
   из девяти цифр. Международные номера сохраняют код страны; локальный
   вьетнамский мобильный `0xxxxxxxxx` приводится к `84xxxxxxxxx`. Неоднозначный
   номер без кода страны не дополняется догадкой. Две карточки с одним полным
   номером закрывают доступ до ручного разбора. Старая Telegram-привязка
   перепроверяется при каждом обращении, client_id не считается доказательством.
3. `0057`: оба кабинета списывают минуты через один service-role RPC. Проверка
   активного сотрудника, блокировка абонемента, проверка статуса/срока/остатка,
   INSERT сессии и изменение статуса выполняются в одной транзакции. Отдельного
   INSERT/fallback/компенсирующего DELETE в обработчиках больше нет. Дата
   инструктора — сегодня во Вьетнаме, офис по-прежнему может указывать прошлую
   дату, но только для действующего на момент записи абонемента.
4. Расчёты зарплаты, CRM, финансов, оплат и выплат прекращаются при ошибке
   зависимого запроса. Частичная загрузка сессий также не считается итогом.

## Порядок выкладки

Потребуется отдельное разрешение на production-операции.

В согласованное окно обслуживания применить **0055 → 0056 → 0057**, затем
выложить соответствующий код и проверить рабочие формы. Не оставлять старый
код после миграций: 0055 намеренно закрывает его прямые записи. Новый код без
0056/0057 также откажет в поиске телефона/списании; небезопасного fallback нет.
Seed на production **не запускать**.

Перед выкладкой read-only сверить старые аномалии, не исправляя деньги наугад:

```sql
select count(*) as invalid_sessions from public.sessions
where amount < 0 or agent_commission < 0 or minutes_used <= 0;
select count(*) as invalid_expenses from public.expenses where amount <= 0;
```

Ограничения 0055 добавлены `NOT VALID`: исторические строки не переписываются,
новые INSERT/UPDATE уже проверяются. Редактирование старой некорректной строки
потребует исправить её нарушение. После согласованной сверки можно отдельно
выполнить VALIDATE CONSTRAINT; это не делается автоматически.

После 0056 проверить количество неоднозначных телефонов без вывода самих номеров:

```sql
select count(*) as ambiguous_phone_groups from (
  select member_phone_key from public.clients
  where member_phone_key is not null
  group by member_phone_key having count(*) > 1
) duplicates;
```

Старые номера без явного кода страны могут перестать давать доступ. Номер в
карточке нужно сверить с клиентом и записать полностью, а не возвращать поиск
по хвосту. Автоматического слияния клиентов или переименования телефонов нет.

## Воспроизведение проверки БД

Нужны Linux/macOS/Windows с поддерживаемой архитектурой, Node.js и свободный
локальный порт 55439. Тест запускает только собственную временную PostgreSQL,
не читает `.env`/DATABASE_URL и не соединяется с Supabase. Он применяет **все**
миграции по порядку, затем seed. Инфраструктурные схемы auth/storage имитируют
минимальное окружение Supabase; RLS и функции проекта выполняются настоящим PG.

Тестовый движок [embedded-postgres](https://github.com/leinelissen/embedded-postgres)
устанавливается отдельно, без изменений package.json/package-lock приложения:

```bash
audit_pg_dir=$(mktemp -d /tmp/flyguru-security-pg-XXXXXX)
npm install --prefix "$audit_pg_dir" --no-audit --no-fund embedded-postgres@17.10.0-beta.17
FLYGURU_TEST_PG_PACKAGE="$audit_pg_dir/node_modules/embedded-postgres/dist/index.js" \
  node --test scripts/test-security-db.mjs
```

Окружение должно разрешать дочерние процессы и локальные порты. Данные тестовой
БД остаются в напечатанном `/tmp/flyguru-security-db-*` для разбора; сервер
останавливается. Тест двух списаний использует два настоящих соединения и
проверяет ожидание блокировки через pg_stat_activity.

Выбран PostgreSQL 17 — та же основная версия, что в supabase/config.toml.

## Границы

Проверено 05.09.2026: 124 unit-теста, семь SQL-сценариев на PostgreSQL 17
(включая весь порядок миграций и seed), 22 браузерных smoke-теста, lint,
TypeScript и git diff --check. Независимое ревью кода и тестов не оставило
обязательных замечаний. Сборка с `--webpack` прошла; стандартный Turbopack
в этом окружении останавливается с EPERM при создании локального порта,
в том числе после запроса расширенных разрешений. Конфигурацию сборки не меняли.

Это не отменяет полномочия администратора напрямую исправлять БД. RPC защищает
штатные списания и конкурирующее изменение самой строки абонемента. Ручные
SQL-корректировки subscription_adjustments администратором следует выполнять
в согласованное окно, а не одновременно с рабочими списаниями.

Задачи по кешированию фото, redirect, завершению заявок/наградам, фотографиям
смен, общей пагинации финансов и CSV оставлены на следующий этап.
